## 依存関係の監査

- `pnpm audit --prod --audit-level high` は、本番の依存関係に、high または critical の既知のアドバイザリがあると、ビルドを失敗させます。このリポジトリに変更がなくても、新しいアドバイザリで、ビルドが赤くなることがあります。対処は、更新または override であり、ステップを飛ばすことではありません。
- すべての依存関係に対する `pnpm audit` は、レポートとしてだけ動きます。2026-11-07 には、開発ツールだけが一覧に出ました(テストランナー、`azure-functions-core-tools`、OpenNext のビルド用ヘルパー)。これらはパッケージに含まれず、ユーザーのマシンでも動かないので、ブロックしません。ときどき、レポートを見てください。
- Next.js は、`postcss` 8.4.31 を厳密に固定していて、これには既知のアドバイザリがあります。`pnpm-workspace.yaml` の `overrides` が、サンプルアプリでは、修正済みのバージョンに引き上げます。ローカルの E2E は、これで合格します。カタログの Next.js のバージョンが、修正済みのものを含むようになったら、override を外してください。overrides を変更したあとは、`pnpm install --lockfile-only` でロックファイルを再生成してください(普通の `pnpm install` は、"Already up to date" と言って、変更を無視しました)。

## シークレットのスキャン

`node scripts/secret-scan.mjs` は、追跡しているファイルを調べます。`--history` は、どのブランチでも、これまでに追加されたすべての行を調べます(完全なクローンが必要です)。独自のルール(`scripts/secret-rules.mjs`: 秘密鍵、ストレージアカウントのキー、SAS 署名、Azure AD のクライアントシークレット、GitHub と npm のトークン、AWS のキー ID、JWT、パスワードの代入)を持つ、小さなスキャナーです。CI が、サードパーティのバイナリをダウンロードするべきではないためです。出力するのは、ファイルとルールで、値は決して出力しません。許可している値は、文書化されている、Azurite の公開の開発用キーだけです。ルールと追跡しているファイルは、単体テストが網羅します。

2026-11-07 に `--history` で実行しました: 何も見つかりませんでした。限界: パターンに基づくので、変わった形のシークレットは見つかりません。Azure のリソース、テナント、サブスクリプションの ID は、この目的ではシークレットではありませんが、あちこちにコピーしないでください。

## ライセンス

`node scripts/license-check.mjs` は、公開するパッケージ、またはワークスペースの本番の依存関係が、MIT、ISC、Apache-2.0、BSD-2-Clause、BSD-3-Clause、0BSD 以外のライセンスを使っていると、失敗します。既知の例外 2 つは、パッケージ名で許可しています。

- `@img/sharp-libvips-*`(`LGPL-3.0-or-later`): `sharp` が同梱する、ビルド済みの `libvips` のバイナリ。
- `caniuse-lite`(`CC-BY-4.0`): Next.js が使うブラウザーのデータ。

どちらも、ユーザーがインストールする peer 依存の `next` から来ます(ADR-0011 で `next` の peer 範囲を追加してからは、`pnpm` が、このパッケージについても一覧にします)。これらは、このパッケージではなく、ユーザーのアプリの zip に入ります。許可されていないライセンスを持つ新しいパッケージは、確認で失敗します。

パッケージには、自身のコード(`dist`、`infra`)しか入っていないので、サードパーティの通知ファイルは要りません。ユーザーのアプリの zip に入るものは、ユーザーの責任であり、このメモには、サンプルが持ち込むものを挙げています。

## まだ対象外のもの

ソフトウェア部品表(SBOM)、リリース時の npm の provenance(フェーズ 4)、CI での Azure Functions Core Tools のダウンロードの固定。
