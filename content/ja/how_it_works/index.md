## リクエストの経路

```
client ──▶ Functions のフロントエンド ──▶ 関数 `server` ──ループバック──▶ Next.js サーバー(同じワーカー)
                                                                          │
                                            キャッシュハンドラー ──▶ Blob(エントリ)+ Table(タグ)
```

- Function App には、**関数が 1 つ**(`server`)あり、ストリーミングを有効にして、すべてのルートに応答します。最初のリクエストで、同じワーカーの中で、Next.js の standalone サーバーが `127.0.0.1:3000` で起動し、ポートが開くまで待ちます。
- すべてのリクエストをそのサーバーに転送し、レスポンスはストリームのまま返します。ルーティング、レンダリング、ミドルウェア、Server Actions、ストリーミング、画像最適化は、Next.js 自身が行います。
- リクエストのボディは、転送の前にバッファします。`Set-Cookie` の値は、Functions のレスポンスの cookie に変換します。ホストが、ヘッダー名ごとに 1 つの値しか保持しないためです。リダイレクトの `Location` ヘッダーには、公開するホストとスキームを戻します。

## キャッシュ

Next.js は、ストレージのために 2 つのインターフェースを呼びます。パッケージは、どちらも Storage 上に実装していて、`withAzure()` が設定します。

| インターフェース | 用途 | ストレージ |
| --- | --- | --- |
| `cacheHandler` | ページ、ルートハンドラー、`fetch` の結果、`revalidateTag`、`revalidatePath` | エントリごとに JSON の Blob 1 つ(`cache` コンテナー。名前はビルド ID とキーのハッシュ) |
| `cacheHandlers` | `'use cache'` | エントリごとに JSON の Blob 1 つ(`use-cache/<ビルド ID>/` の下) |
| タグ(どちらも) | 再検証の状態 | テーブル `tagcache`: 各タグを最後に再検証した時刻 |

エントリは、タグのどれかが、書き込みのあとで再検証されると、破棄されます。再検証で何も削除しないので、タグごとに小さな書き込みが 1 回です。キーにはビルド ID が入ります。新しいデプロイは、空のキャッシュで始まり、古いビルドのエントリは、読まれません(ライフサイクルルールが `--cache-retention-days` のあとで削除します)。

**時間ベースの ISR** は、Next.js 自身のものです。`revalidate` より古いエントリを見つけたリクエストには、古いページをすぐに返し(`x-nextjs-cache: STALE`)、サーバーが、バックグラウンドで、同じプロセスの中でページを再生成します。キューはありません。その間にインスタンスが取り除かれると、再生成は失われ、次のリクエストが、もう一度始めます。

**プリレンダリングされたページ。** `next build` は、ページを `.next/server` にプリレンダリングします。Blob にないとき、キャッシュハンドラーが、そこから読みます。そのため、ビルドされたページは、最初のリクエストからキャッシュにあり、フォールバックのないルート(`dynamicParams = false`)も動きます。`deploy` が実行する `next-on-azure prime` は、プリレンダリングされたすべてのルートを 1 回要求して、インスタンスを温めます。

## `after()` などの遅延処理

アイドルのインスタンスは、約 1.5〜3.5 分で取り除かれ、それより長く続く遅延処理は失われます。そのため、レスポンスが終わる前に登録された処理が終わるまで、レスポンスを開いたままにします(最大 `WAIT_UNTIL_MAX_SECONDS`、既定は 220 秒)。`--wait-until detach` は、代わりに、すぐにレスポンスを終えます。

## パッケージ化

`next-on-azure package` は、`.next/standalone` から Function App を作ります。

1. Next.js のバージョンと、Server Actions のキーを確認します。
2. standalone のディレクトリをコピーし、pnpm の `node_modules` を、シンボリックリンクのない通常のツリーに変えます(Azure は、リンクを落とします)。
3. `.next/static` と `public/` を `server.js` の隣に、Linux x64 のバイナリ付きの完全な `sharp` パッケージとともにコピーします。
4. Functions のエントリと `host.json` を足し、`@azure/functions` をインストールして、zip にします。
